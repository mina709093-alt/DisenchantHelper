# DisenchantHelper (마력 추출 도우미) 1.0.8

## 1.0.8 변경 사항
- 마법부여(마력 추출)를 배우지 않은 캐릭터에서는 애드온이 자동으로 꺼집니다: 가방 테두리, 툴팁 줄, [일괄 추출] 버튼, 경매장 체크박스, 단축키 추출이 모두 표시되지 않습니다.
- 나중에 마법부여를 배우면 재접속 없이 자동으로 켜집니다. (켜고 끄는 버튼은 없습니다)
- 상수팩 업데이트 알림 기능 포함 (/상수팩)

## 1.0.6 변경 사항
- 마력 추출 가능 테두리를 초록색에서 **보라색**으로 바꿨습니다. 고급(초록) 등급 아이템 테두리를 표시하는 다른 애드온과 헷갈리지 않게 하기 위해서입니다.
- Alt+좌클릭 대기 상태의 칸 색은 보라 테두리와 구분되도록 옅은 노란색으로 바꿨습니다.

## 1.0.5 변경 사항
- 일괄 추출 창은 가방의 [일괄 추출] 버튼(또는 `/dh`)으로 열 때만 표시됩니다. 가방 아이콘이나 B 키로 가방을 열면 기존처럼 가방만 열립니다.
- 가방을 닫으면(B 키, 가방 아이콘, 닫기 버튼) 열려 있던 일괄 추출 창도 함께 닫힙니다. 선택 목록은 그대로 남습니다.
- `/dh`로 창을 열 때 가방이 닫혀 있으면 가방도 함께 엽니다.

## 1.0.4 변경 사항 (테스트 기능)
- 사전 확인: 가방을 열면, 툴팁 근거 없이 규칙으로만 "가능" 판정된 장비를 아이템 종류당 한 번씩 투명한 툴팁으로 실제 표시해서 게임이 붙이는 "마력 추출 불가" 줄을 미리 읽습니다. 마우스를 올리지 않아도 초록 테두리가 정리되는 것이 목표입니다.
- 1단계는 애드온 전용 툴팁, 1단계에서 문구가 없으면 2단계로 기본 툴팁을 쉬고 있을 때만 0.25초 정도 투명하게 빌려 씁니다. 전투 중에는 멈췄다가 전투 후 재개합니다.
- 확인 결과 "추출 불가"로 바뀐 아이템은 채팅창에 한 줄 안내합니다.
- `/dh 진단`에 "사전 확인" 항목(어느 단계에서 찾았는지 개수)이 추가됐습니다.

## 1.0.3 변경 사항
- 게임 툴팁의 "마력 추출 불가" 줄이 애드온이 읽는 시점보다 늦게 붙는 경우에도 잡도록, 툴팁이 다 그려진 뒤(다음 화면 갱신, 0.3초 뒤, 툴팁 표시 시점) 한 번 더 확인합니다. 결과가 바뀌면 기록하고, 열려 있는 툴팁의 "마력 추출:" 줄과 가방·경매장 표시도 바로 고칩니다.
- 툴팁 글자 비교 시 색상 코드, 보이지 않는 공백, 줄바꿈 문자를 제거하고, 앞뒤에 다른 글자가 붙어 있어도 "마력 추출 불가"를 알아봅니다.
- `/dh 툴팁`에 현재 화면 툴팁의 줄과 글자 코드를 추가했습니다.

## 1.0.2 변경 사항
- Alt+좌클릭으로 마력 추출이 시전되지 않던 문제를 고쳤습니다. 보안 버튼은 조합키를 누르고 있으면 `type1` 대신 `*type1`/`alt-type1` 속성을 찾기 때문에, 모든 조합키에 적용되는 `*` 속성을 함께 지정합니다. 조합키가 들어간 단축키로 [선택 아이템 추출]을 누를 때도 같은 방식으로 동작합니다.
- 클릭은 들어왔는데 시전이 시작되지 않으면 채팅창에 한 번 안내합니다.

## 1.0.1 변경 사항
- 게임 툴팁에 "마력 추출 불가"가 나오는 아이템(예: 마법부여로 만든 하급 마술봉)을 "가능"으로 잘못 판별하던 문제를 고쳤습니다.
- 툴팁 확인 경로 3단계: ① 이전에 확인한 기록(itemID 단위) → ② 숨겨진 검사용 툴팁(실제 게임 툴팁과 같은 방식으로 그림) → ③ 툴팁 데이터(C_TooltipInfo, 색상 코드 제거 후 비교).
- 안전장치: 아이템에 마우스를 올려 게임 툴팁이 뜨면, 그 툴팁의 마력 추출 문구를 바로 기록하고 가방·경매장 표시를 다시 갱신합니다.
- 같은 아이템 종류는 경매장 판별에도 확인 기록을 그대로 씁니다.
- `/dh 툴팁` 추가: 가방 아이템에 마우스를 올린 채 입력하면 경로별 판별 근거를 복사할 수 있습니다.

와우 포에버(WoW: Forever, Interface 16001)용 애드온입니다.

## 1단계: 기술 검증 보고서

### 전제: 대상 클라이언트
- 와우 포에버는 클래식 클라이언트가 아니라 **Midnight 리테일 엔진** 위에서 돌아가고, 인터페이스 번호만 16001로 따로 씁니다. 그래서 클래식 전용 API(구형 경매장 `QueryAuctionItems`, `GetContainerItemInfo` 등)를 기준으로 만들면 동작하지 않습니다.
- 그래서 이 애드온은 리테일 계열 API(`C_Container`, `C_Item`, `C_TooltipInfo`, `TooltipDataProcessor`, `AuctionHouseFrame`, `SecureActionButtonTemplate`)를 기본으로 씁니다. 구형 API는 없을 때를 대비한 보조 경로로만 넣었습니다.
- 포에버의 애드온 제한(보호 값, 전투 중 비공개 정보)은 주로 **전투·유닛·주문 정보**에 걸립니다. 가방, 아이템 정보, 경매장 목록은 전투 밖에서 읽을 수 있습니다.
- 이전 작업에서 확인한 클라이언트 특성: `/script` 미동작, 매크로 조건문(`[mod:]`, `[nobuff]`) 미지원. 그래서 보안 상태 드라이버(`RegisterStateDriver`, 매크로 조건문 기반)는 쓰지 않았습니다.

### A. 아이템의 마력 추출 가능 여부를 API로 확인할 수 있는가? → **조건부 가능**
- `IsDisenchantable` 같은 **전용 API는 없습니다.**
- 대신 아래 정보를 조합해서 판별합니다.
  | 확인 항목 | 사용 API |
  |---|---|
  | 아이템 분류(무기/방어구), 세부 분류, 장착 부위 | `C_Item.GetItemInfoInstant` (즉시 응답) |
  | 품질(고급·희귀·영웅만 가능) | 가방 정보의 `quality`, `C_Item.GetItemQualityByID` |
  | 귀속 유형(퀘스트 아이템 제외) | `C_Item.GetItemInfo` 14번째 반환값 |
  | 아이템 레벨 | `C_Item.GetDetailedItemLevelInfo` / 경매장 `itemKey.itemLevel` |
  | 툴팁 문구(보조 근거) | `C_TooltipInfo` + 클라이언트 GlobalStrings `ITEM_DISENCHANT_NOT_DISENCHANTABLE` / `ITEM_DISENCHANT_ANY_SKILL` / `ITEM_DISENCHANT_MIN_SKILL` |
  | 마력 추출 습득 여부 | `IsPlayerSpell(13262)` 외 |
  | 마법부여 숙련도 | `GetProfessions` + `GetProfessionInfo`(skillLine 333), 없으면 `GetSkillLineInfo` |
- 제외 규칙: 속옷, 휘장, 가방, 화살통, 외형 아이템, 낚싯대, 퀘스트 아이템, 일반 등급 이하, 전설 이상, 사용자 제외 목록(`/dh 제외`).
- 툴팁에 마력 추출 문구가 나오면 그 내용을 규칙보다 우선합니다. 툴팁 문자열은 클라이언트에 있는 한국어 원문을 그대로 쓰고 직접 적어 넣지 않았습니다.
- 툴팁 근거 없이 판단하기 어려운 "기타 무기(도구류)"는 **미확인**으로 둡니다.
- **확인 필요:** 포에버의 요구 숙련도 기준은 공개된 자료가 없습니다. 툴팁에 요구 숙련도가 나오지 않으면 클래식 기준표(아이템 레벨 20 이하: 1, 21~25: 25, 이후 5레벨마다 +25, 61 이상: 225)로 추정합니다. 실제로 시도했다가 "숙련도 부족" 오류가 나면 그 아이템은 바로 추출 불가로 바뀝니다. 아이템은 소모되지 않습니다.

### B. 인벤토리 아이템의 마력 추출 가능 여부를 자동 판별할 수 있는가? → **가능**
- 가방 아이템은 링크, 품질, 툴팁(`C_TooltipInfo.GetBagItem`)까지 모두 읽을 수 있어서 판별 정확도가 가장 높습니다.
- 아이템 정보가 아직 서버에서 오지 않았으면 **미확인**으로 두고, `GET_ITEM_INFO_RECEIVED` 이벤트가 오면 다시 판별합니다.

### C. 경매장 검색 결과의 아이템도 판별할 수 있는가? → **조건부 가능**
- 경매장 결과는 내가 가진 아이템이 아니라서 `itemKey`(itemID, 아이템 레벨, 접미사)만 받습니다. 귀속 상태나 개별 아이템 상태는 알 수 없습니다.
- 분류, 품질, 부위, 레벨은 itemID로 확인할 수 있습니다. 툴팁은 `C_TooltipInfo.GetItemKey`로 가능할 때만 보조로 씁니다.
- 판별하지 못한 결과는 **목록에서 뺍니다.** 정보가 나중에 도착하면 원본 결과를 기준으로 다시 거릅니다.

### D. 기존 경매장 검색 필터에 체크박스를 추가할 수 있는가? → **가능 (결과 필터링은 조건부 가능)**
- 체크박스 추가: 가능합니다. 검색 줄(SearchBar)의 **필터 버튼 옆**에 기본 체크박스 템플릿으로 넣습니다. 별도 탭은 만들지 않습니다. 필터 드롭다운 메뉴 안에 넣는 방법은 메뉴 식별자가 공개돼 있지 않아 안정성이 낮아서 쓰지 않았습니다.
- 결과 필터링: 서버 검색 조건(`C_AuctionHouse.SendBrowseQuery`)에는 마력 추출 조건이 없습니다. 그래서 서버가 돌려준 결과 목록(`BrowseResultsFrame.browseResults`)을 화면에 그리기 전에 클라이언트에서 거릅니다.
  - `hooksecurefunc`로 결과 갱신 함수 뒤에만 붙기 때문에 원래 함수, 검색창, 검색 버튼, 구매 과정은 그대로입니다.
  - 원본 결과를 따로 보관했다가 체크를 해제하면 그대로 복원합니다.
  - 경매장 구매 함수는 보호 함수가 아니라 하드웨어 입력만 필요해서, 목록을 걸러도 구매가 막히지 않습니다. Auctionator 같은 애드온도 같은 방식으로 구매합니다.
- **확인 필요:** 포에버의 경매장 결과 프레임 구조가 리테일과 다르면 필터 연결에 실패합니다. 이때는 체크박스 툴팁과 채팅에 이유가 표시되고, 경매장 기본 기능에는 영향이 없습니다.

### E. 여러 아이템을 선택하고 순차적으로 마력 추출할 수 있는가? → **조건부 가능**
- 선택, 목록 관리, 진행 상태 표시, 이동·삭제 추적은 **가능**합니다.
- **자동 연속 추출은 불가능**합니다. 마력 추출은 보호된 주문이라 하드웨어 입력(클릭이나 키 입력) 1번에 시전 1번만 허용됩니다. 애드온이 혼자서 다음 아이템을 이어서 추출할 수는 없고, 이 제한을 우회하지 않습니다.
- 대신 이렇게 구현했습니다.
  - **[선택 아이템 추출]** 버튼은 `SecureActionButtonTemplate` 보안 버튼입니다. 누를 때마다 목록의 **다음 아이템 1개**를 자동으로 대상으로 지정해 추출합니다. 클릭 직전에 대상을 지정하므로 아이템이 움직여도 정확합니다.
  - **단축키 지정**: 게임 단축키 설정 > 애드온 > "선택 아이템 추출 (다음 아이템)". 키를 연타하면 하나씩 순서대로 진행됩니다. TotemChain의 연속 클릭+키 지정 방식과 같은 원리입니다.
  - 다음 대상은 가방에서 **깜빡이는 밝은 파란 테두리**와 목록의 "다음" 표시로 알려 줍니다.
  - 추출 진행 중, 추출 완료, 실패, 남은 아이템 수, 완료 개수를 표시합니다.

### F. SHIFT + 좌클릭으로 마력 추출을 실행할 수 있는가? → **조건부 가능**
- 단축키 감지는 가능합니다(`IsShiftKeyDown` 등, `MODIFIER_STATE_CHANGED`).
- 구현 방식: 조합키를 누른 상태로 추출 가능한 아이템에 마우스를 올리면, 그 칸 위에 **보안 버튼(`SecureActionButtonTemplate`, type=spell, spell=13262, target-bag/target-slot)**이 겹쳐집니다. 이 상태에서 **실제로 클릭해야만** 게임이 주문을 시전합니다. 애드온 Lua 코드가 주문을 직접 시전하지 않습니다.
- 조합키를 떼면 겹친 버튼이 사라지고 원래 클릭 기능(이동, 장착, 사용)이 그대로 돌아옵니다.
- 제한
  - **전투 중에는 동작하지 않습니다.** 전투 중에는 보안 버튼을 옮기거나 표시할 수 없습니다.
  - **Shift + 좌클릭은 기본 기능(채팅 링크 넣기, 묶음 나누기)과 겹칩니다.** 그래서 기본값을 **Alt + 좌클릭**으로 정했습니다. Alt + 좌클릭은 가방 아이템에 기본 동작이 없습니다. `/dh 키 shift`로 Shift로 바꿀 수 있지만, 그러면 추출 가능한 장비는 Shift+클릭으로 링크를 넣을 수 없습니다.

## 설계 요약

| 기능 | 동작 |
|---|---|
| 판별 엔진 | 경매장, 인벤토리, 일괄 추출이 같은 엔진을 씁니다. 상태는 가능, 불가능, 미확인 세 가지이고, 미확인은 절대 가능으로 표시하지 않습니다. |
| 인벤토리 표시 | 가방을 열면 바로 적용됩니다. ON/OFF 버튼은 없습니다. 추출 가능 아이템에만 **보라 테두리**를 아이콘 바깥 2px에 그려서 아이콘, 수량, 귀속 표시를 가리지 않습니다. |
| 일괄 추출 선택 | 가방 왼쪽 아래 **[일괄 추출]** 버튼 → 창이 열린 동안 보라 테두리 아이템을 **그냥 클릭**하면 선택/해제됩니다. 선택은 **파란 테두리**로 표시됩니다. 초록 테두리가 없는 아이템은 평소처럼 클릭됩니다. |
| 선택 목록 창 | 아이콘, 이름(등급 색), 수량, 개별 선택 해제(X), 전체 선택 해제, 추출 가능 전체 선택, 선택된 아이템 수, 남은 아이템, 상태를 보여 줍니다. |
| 아이템 추적 | 아이템 GUID로 추적합니다. 가방 사이를 옮겨도 선택이 유지되고, 삭제·판매·추출되면 목록에서 자동으로 빠집니다. |
| 툴팁 | 장비 툴팁에 "마력 추출: 추출 가능 / 추출 불가(이유) / 미확인" 한 줄을 추가합니다. |
| 성능 | 이벤트 기반으로만 동작하고 OnUpdate 반복문은 없습니다. 판별 결과는 아이템 링크 단위로 캐시합니다. 테두리 프레임은 필요한 칸에만 처음 한 번 만듭니다. |

### 색상 규칙
- 보라 테두리: 마력 추출 가능
- 파란 테두리: 일괄 추출에 선택됨
- 깜빡이는 밝은 파란 테두리: 다음 추출 대상
- 테두리 없음: 추출 불가 또는 미확인 (기본 표시 유지)

## 설치

1. `DisenchantHelper` 폴더를 통째로 아래 경로에 넣습니다.
   `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\DisenchantHelper\`
2. 폴더 안에 `DisenchantHelper.toc`, `Core.lua`, `Disenchant.lua`, `Bags.lua`, `AuctionHouse.lua`, `BatchDisenchant.lua`, `UI.lua`, `Bindings.xml`이 바로 보여야 합니다. 폴더가 두 번 겹치면 안 됩니다.
3. 게임을 실행하고 캐릭터 선택 화면의 애드온 목록에서 "마력 추출 도우미"를 켭니다.
4. (선택) 설정 > 단축키 > 애드온 > 마력 추출 도우미 > "선택 아이템 추출 (다음 아이템)"에 키를 지정합니다.

## 명령어
| 명령 | 설명 |
|---|---|
| `/dh` | 일괄 추출 창 열기/닫기 + 도움말 |
| `/dh 키 alt` / `shift` / `ctrl` | 단축키+좌클릭 추출 조합키 변경 |
| `/dh 제외 [아이템 링크]` | 마력 추출 제외 목록에 추가/삭제 |
| `/dh 진단` | 기술 진단 정보 복사 창 (버그 제보용) |
| `/dh 툴팁` | 마우스를 올린 가방 아이템의 판별 근거 복사 창 |
| `/dh 오류` | 오류 기록 복사 창 |

## 테스트 방법 (7단계: 통합 테스트)

마법부여를 배운 캐릭터로, 고급(초록) 이상 장비를 몇 개 가방에 넣고 시작하세요.

1. **로딩 / 진단**
   - 접속 후 `/dh 진단` → `Interface: 16001`, `C_Container: true`, `마력 추출 습득: true`, `마법부여 숙련도: (숫자)`를 확인합니다.
   - `툴팁 문자열` 항목이 "없음"이면 툴팁 근거 없이 규칙만으로 판별한다는 뜻입니다(정상 동작).
2. **인벤토리 표시**
   - 가방을 열면 초록·파랑·보라 장비에 보라 테두리, 흰색·회색 아이템과 재료에는 테두리가 없어야 합니다.
   - 장비에 마우스를 올리면 툴팁 맨 아래에 "마력 추출: 추출 가능"이 나옵니다.
   - 아이템 이동, 가방 간 이동, 판매, 삭제, 새 아이템 획득 후에도 테두리가 맞게 따라가는지 확인합니다.
   - 통합 가방 / 개별 가방 설정을 둘 다 확인합니다.
3. **Alt + 좌클릭 추출**
   - 보라 테두리 아이템 위에서 Alt를 누르면 칸이 옅은 노란색으로 바뀌고, 클릭하면 마력 추출이 시전됩니다.
   - Alt를 떼면 평소처럼 아이템을 들어 옮길 수 있는지 확인합니다.
   - 전투 중에는 동작하지 않는 것이 정상입니다.
4. **일괄 추출**
   - 가방 왼쪽 아래 [일괄 추출] → 창이 열린 상태에서 보라 테두리 아이템 클릭 → 파란 테두리, 목록에 추가되는지 확인합니다.
   - 같은 아이템을 다시 클릭하면 선택 해제됩니다. X 버튼으로 개별 해제, [전체 선택 해제], [추출 가능 전체 선택]을 확인합니다.
   - 선택한 아이템을 다른 가방으로 옮겨도 선택이 유지되는지 확인합니다.
   - [선택 아이템 추출]을 누를 때마다 1개씩 추출되고, 상태가 "추출 진행 중 → 추출 완료"로 바뀌고 남은 아이템 수가 줄어드는지 확인합니다.
   - 지정한 단축키를 연타해도 같은 결과인지 확인합니다.
5. **경매장 필터**
   - 경매장을 열면 검색 줄의 필터 버튼 옆에 "마력 추출 가능" 체크박스가 보입니다.
   - 체크하고 "가죽" 같은 단어로 검색 → 추출 가능한 장비만 남는지, 체크박스 툴팁의 "추출 가능 N개 / 전체 M개"를 확인합니다.
   - 체크를 해제하면 원래 결과가 모두 다시 보여야 합니다.
   - 걸러진 목록에서 아이템을 골라 실제로 구매·입찰이 되는지 확인합니다.
6. **예외 상황**
   - 마법부여가 없는 캐릭터: 오류가 없어야 하고, 테두리는 표시되지 않습니다(판별 결과는 "마법부여 미습득").
   - Baganator, Bagnon 같은 가방 애드온을 쓰면 그 애드온의 가방에는 테두리가 나오지 않습니다. 툴팁 표시, 일괄 추출 창의 [추출 가능 전체 선택], 단축키 추출은 계속 동작합니다.

### 문제가 생기면
`/dh 진단`과 `/dh 오류`의 내용을 복사(Ctrl+A, Ctrl+C)해서 전달해 주세요. 특히 아래 항목을 보면 원인을 바로 알 수 있습니다.
- `경매장 필터: 사용 불가: ...` → 포에버의 경매장 구조가 리테일과 다름 (프레임 이름 확인 후 수정)
- `가방 프레임 연결: 0개` → 가방 프레임 이름이 다름
- `마법부여 숙련도: 확인 불가` → 포에버 전문기술 API가 다름 (그래도 주문 습득이 확인되면 "가능"으로 표시하고 숙련도 검사만 건너뜀)

## 알려진 제한 사항
- 자동 연속 추출(한 번 클릭으로 여러 개)은 게임 보안 정책상 불가능합니다. 클릭이나 키 입력 1번에 1개씩입니다.
- 전투 중에는 단축키 추출과 일괄 추출 창을 쓸 수 없습니다. 창은 전투 시작 직전에 자동으로 닫히고, 선택 목록은 그대로 남습니다.
- 경매장 필터는 서버가 돌려준 결과 안에서 거르는 방식이라, 결과가 많은 검색은 일부만 받은 상태에서 먼저 걸러지고 추가 결과가 오면 이어서 걸러집니다.
- 경매장 결과는 개별 아이템 상태를 알 수 없어서 인벤토리보다 판별 근거가 적습니다.
- 포에버의 실제 요구 숙련도 기준은 공개 자료가 없어 추정치를 씁니다. 툴팁 문구나 실제 시도 결과가 있으면 그쪽을 우선합니다.
- 포에버 베타에서는 애드온 설정이 다음 접속 때 다시 읽히지 않는 사례가 보고돼 있습니다. 그 경우 `/dh 키` 설정과 제외 목록이 접속할 때마다 초기화될 수 있습니다(기본값 Alt로 동작).
